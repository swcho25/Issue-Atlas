## 1. place_id

| 단위 | 형식 | 예 | 어디에 |
| --- | --- | --- | --- |
| 시도 | `kr-<KOSIS 2자리>` | 통합시 `kr-12` · 광주 5개 구 `kr-29` · 옛 전남 `kr-46` · 충남 `kr-44` | `place`(목록에는 안 나감), 이동 도착점 |
| 시군구 | `kr-<KOSIS 새 시군구 5자리>` | 동구 `kr-12210` · 서구 `kr-12240` · 남구 `kr-12270` · 북구 `kr-12300` · 광산구 `kr-12330` · 여수시 `kr-12130` | 질문 · 카드 판정 · 통계의 단위 |
| 행정동 | `kr-<시군구 5자리><SGIS 읍면동 3자리>` | 계림1동 `kr-12210560` | 시군구 안의 지도 · 기사 좁히기만. 판정은 시군구 |
| 기사 위치 읍면동 | 지금 법정동 `kr-<10자리>` → 행정동 `kr-<8자리>` 로 바뀜 | — | `news_event.place_id` 만(`place` 행 없음). **동결 밖** |

- 옛 `plc_*` 는 404. 통계 · 관측 행의 질문 지역 고르기는 「앞자리가 같은 것」(`starts_with`). 기사 고르기는 아래 「아직 안 정한 것」
- **받는 쪽은 place_id 의 길이 · 자리 수로 뜻을 해석하지 않는다.** 단위는 응답의 `level` 등 칸으로 보고, 지역 포함은 앞자리만 비교한다. 그래야 기사 위치 · 측정소 형식이 바뀌어도 화면이 깨지지 않는다
- 측정소: `kr-<부모 시군구 5자리>-s<에어코리아 측정소 코드>`(예 `kr-12130-s336121`, V0032 · [P3 v0.8 「측정소 ID」](p3/README.md), 동결 전 2026-11-03 바꿈). 옛 `plc_stn_*` 는 없다

## 2. 관측 행 `observation`

통계 한 값 · 기사 한 건 = 한 행. 판정과 응답 `series[]` · `articles[]` 는 이 view 만 읽는다.

- 칸: `obs_id` · `what_type` · `what_id` · `what_kind` · `tags` · `when_start` · `when_end`(미포함) · `when_unit` · `when_precision` · `place_id` · `to_place_id` · `station_id` · `lon` · `lat` · `location_precision` · `value` · `unit` · `status` · `source_table` · `spec_id` · `summary`
- 값이 없으면 `value = null` + `status`(`not_published` …). 0으로 채우지 않는다
- 연령은 지표 ID 에 넣는다(SP01 `locator.C3` 905 → `population_net_migration_19_39`). 연 합계 · 비율은 행으로 만들지 않는다
- **동결 밖:** 기사 `tags` 는 기사 분류(P4) 전까지 빈 배열 → `articles[]` 도 지금은 빈 배열. 측정소 행의 `place_id` 는 읍면동이 아니라 시군구

## 3. C2 응답

- 엔드포인트: `GET /v1/places` · `GET /v1/places/{place_id}/cards` · `POST /v1/questions` · `GET /v1/arguments/{run_id}` · `GET /v1/evidence/{evidence_id}` · `GET /v1/observations` · `GET /v1/sources` (+ 관리자 `/v1/admin/**`)
- 데모 흐름: `POST /v1/questions` → `run_id` → `GET /v1/arguments/{run_id}` 응답 하나로 6칸 · 막대 · 기사 점을 그린다. 화면 추가 요청 없음
- argument 최상위 칸(모두 필수): `schema_version` · `run_id` · `question` · `card_version` · `formula_version` · `taxonomy_version` · `run_status` · `created_at` · `evidence_table`(4행) · `comparability` · `claim` · `data` · `warrant` · `qualifier` · `rebuttals` · `ceiling` · `series` · `articles`
- `series[]` 공통 칸: `unit` · `periods[]`(`YYYY-MM`, 질문 기간의 달 모두) · `values[]` · `statuses[]`(길이 같음). 모양은 칸으로 갈린다: `to` 있음 = 이동 · `tag` 있음 = 기사 건수 · `coordinates` 있음 = 측정소 지도 · 없음 = 월별 막대
- `articles[]` 칸: `id` · `date` · `place_id` · `point` · `precision` · `summary` · `place_name` · `url`(원문 링크, null 허용. 본문 없음)
- enum 은 [c2 README 「enum」](c2/README.md#enum) 9개 모두 그대로: `evidence_status` · `run_status` · `evidence_kind` · `claim` · `claim_level` · `provenance` · `qualifier_grade` · `rebuttal_status` · `source_grade`
- 공통: snake_case · 시각은 오프셋 있는 ISO 8601 · 기간 `[start, end)` · 좌표 `[경도, 위도]` · 모든 객체 `additionalProperties: false` · 점수 · 순위 · 수치 신뢰도 칸 없음

## 동결 뒤 바꾸는 법 (11/13 C2 v1 까지)

- **안 바꾼다:** 위 칸 이름 · 타입 · 필수 여부 · enum 값 · ID 형식, **칸 추가 · 삭제**(모든 객체가 `additionalProperties: false` 라 칸을 더해도 받는 쪽 검증이 깨진다). 꼭 바꿔야 하면 주는 쪽 · 받는 쪽 둘 다 리뷰한 MR 로, 이 문서와 원본 계약의 변경 이력을 같은 MR 에서 고친다
- **정함(2026-11-02, P5 최동준):** 완전한 연 값이 3개 미만이면 카드 적용 조건(B6) 미충족 → `run_status = unsupported` · `claim = insufficient`. 지금 구현은 `run_status` 가 이와 달라 P5 가 고친다(값만 바뀌고 칸은 그대로)
- **해도 된다:** 값이 바뀌는 것(판정 결과, 근거 행), 예시 파일 값, 빈 배열 · null 칸에 값이 차는 것(`articles[]` · `url` · `data.statistics`)
