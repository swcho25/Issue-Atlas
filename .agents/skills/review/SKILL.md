# review

1. 범위: `git diff origin/dev...HEAD` + 커밋 안 된 변경. `origin/dev` 가 없으면 `origin/main`.
2. 실행 계획 `docs/plans/active/<branch>.md` 의 완료 조건과 대조한다 — 빠진 것, 범위를 넘은 것.
3. 아래 순서로 본다. 확실한 것만 적고, 추측은 「확인 필요」로 따로 둔다.
   1. **정확성**: 경계값, null, 시간대(UTC), 에러 처리, 트랜잭션
   2. **계약**: API·DB 를 바꿨는데 `contracts/`·Flyway 마이그레이션이 없다 / 기존 마이그레이션을 고쳤다
   3. **구조**: frontend FSD 방향·public API, 서버·클라이언트 경계 / backend 패키지 규칙 (`frontend/AGENTS.md`, `backend/AGENTS.md`)
   4. **테스트**: 바뀐 동작을 확인하는 테스트가 있는가
   5. **보안**: 비밀값, 입력 검증, 로그에 개인정보
4. 결과 형식 (심각한 것부터)

```
[필수] 파일:줄 — 무엇이 틀렸고 어떤 상황에서 문제가 되는지
[권장] 파일:줄 — …
[확인 필요] …
완료 조건: 3/3 충족 | 미충족 항목
```

5. 고치라는 요청을 받기 전에는 수정하지 않는다.
