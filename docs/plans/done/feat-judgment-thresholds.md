### 결정 (2026-11-02, 최동준)
- **청년 연령대 19–39세.** 근거: 회사 노션 「2주 개발 플랜」 표 1 #2 결정 칸 「청년(19–39세) 순이동 월(SP01 905)」, 지표 사전 · 관측 view · 수집 밴드가 모두 19–39. 15–39 는 양식 v1.1 초안에만 있었다. 법령 기준이 아니라 통계 공표 · 수집 범위(KOSIS SP01 905 밴드)다. 청년기본법은 19–34 라서 화면은 「청년(19–39세)」로 범위를 같이 보여 준다
- **C1 은 변화 폭 임계 없이 부호와 방향 패턴으로 판정**(표 1 #2). 위에서부터 처음 맞는 것: 완전한 해 3개 미만 → 근거 부족 · 모두 음수 + 절대값 해마다 증가 → 청년 순유출 확대(`increasing`) · 모두 음수 + 해마다 감소 → 축소(`decreasing`) · 앞선 해에 음수가 있고 마지막 해 양수 → 순유입 전환(`decreasing`) · 그 외(같은 값, 오르내림, 모두 양수) → 불분명
  - 3년보다 긴 기간은 「기간 안 모든 해」로 본다. 12개월이 다 있는 해만 연 값이 있고, 빠진 해는 건너뛰고 남은 해를 순서대로 본다. 0 은 음수도 양수도 아니다
  - 순유입 전환은 판정값에 맞는 값이 없어 새로 만들지 않고 `decreasing` 에 화면 문구만 다르게 둔다
  - `formula_version` 은 0.1 을 그대로 쓴다. 0.1 로 나온 판정 결과가 아직 없어(실행부 없음) 꼬이는 데이터가 없다
- **A3 PM2.5 는 끝해 − 첫해 연평균 차이 ±3µg/m³**(표 1 #3). 강수 · 풍향만으로 연평균이 1~2µg/m³ 움직여 ±2 면 기상 변동이 악화로 찍힌다. +3 이상 악화(`increasing`), −3 이하 개선(`decreasing`), 사이 불분명. 경계값 포함
  - 월평균은 가동률 75% 이상인 달만(air_monthly), 연평균은 유효한 달 9개 이상일 때만. MVP 는 월평균 → 연평균으로 판정하고 나쁨 일수는 MVP 뒤
  - **측정소 고정**: 기간 안 모든 해에 연평균이 있는 측정소(공통 측정소)만 평균한다. 없으면 `not_comparable`. 결과가 0.1 과 달라져 `a3-pm25-diff-0.2` 로 올린다
  - 대기환경기준(연평균 15µg/m³) 같은 기준선은 판정이 아니라 화면 맥락 표시용이다
- **이름 · 모양은 #171 그대로**: `rule_id` `net_migration_trend` · `first_last_diff`, A3 `thresholds` `{worse, better, unit}`, `min_years` 는 규칙 최상위
- **승인자**: 기준값의 업무 결정은 대표(2026-11-01, 표 1 결정 2 · 3 · 4 · 5 — 카드 `approval`)와 세부 해석(위 목록, 2026-11-02 최동준). DB 저장 승인(`card_approval.approved_by`)은 운영 관리자 계정의 로그인 이메일 — 관리자 API 로 승인할 때 남는 값과 같다
- **운영 seed 는 Flyway 밖 SQL 파일**을 개발 · 운영 DB 에 한 번씩 손으로 실행한다. 이유: C3 계약상 Flyway 는 운영 승인본을 seed 하지 않는다 · Flyway 에 넣으면 테스트 DB 에도 들어가 C1 이 legacy 라고 가정한 통합 테스트가 깨진다 · 관리자 계정은 Flyway 뒤 앱이 켜질 때 `ADMIN_EMAIL` 로 만들어져 마이그레이션 시점에 없고 이메일을 저장소에 적을 수 없다
